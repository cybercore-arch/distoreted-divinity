# Distorted Divinity — архитектура

Движок: **Godot 4.3+ (GDScript)**. Разрешение: **480×270**, целочисленный масштаб.
Арт: пиксель-арт, персонажи/NPC 32×32, предметы 64×64.

## Главные правила

1. **Контент = данные.** Оружие, враги, комнаты, регионы, предметы, боссы — это `.tres` ресурсы
   в `data/`. Новый контент добавляется файлом данных, а не правкой кода.
2. **Сущности собираются из компонентов** (`Health`, позже `Shooter`, `Mover`), а не из наследования.
3. **Системы общаются через `EventBus`** (`core/event_bus.gd`), без прямых ссылок друг на друга.
4. **Три независимых слоя забега:** мета-карта → этаж → комната. Комната ничего не знает про этаж.
5. **Run State и Meta Save раздельно:** что сбрасывается за забег и что остаётся навсегда.
6. **Спрайты подменяются данными:** у сущности есть поле `sprite`/`icon`; пока оно пустое,
   рисуется цветной плейсхолдер.
7. **Дерево сцены меняется только отложенно** (`call_deferred`), если причина — физический сигнал.

## Структура папок

```
core/       автозагрузки: event_bus, input_setup, content_registry, debug_state, console/
            (позже game_state, save_system)
data/       схемы ресурсов (*.gd) и сами ресурсы: fire_modes/, weapons/, enemies/, patterns/
            (позже regions/, items/, bosses/)
entities/   player, enemy, projectile, melee, zone, pedestal, components/
rooms/      room (комната из RoomData), door
systems/    test_floor_builder (позже run_graph, floor_generator, bullet_pool, boss_fsm)
scenes/     корневые сцены (сейчас test_floor — тестовый этаж 0.0)
ui/         HUD, меню
assets/     спрайты и музыка
```

## Управление

WASD — движение · стрелки — стрельба · Q — смена оружия (2 слота) ·
E — альт (когда шкала заряда полная) · пробел — рывок (короткая неуязвимость, перезарядка 5 с).
Подбор оружия — касанием пьедестала. Раскладка регистрируется кодом в `core/input_setup.gd`.

## Оружие

`WeaponData` = название + редкость + теги + два `FireMode` (`primary` на стрелках, `alt` на E).

`FireMode.kind` определяет поведение режима:

| kind         | что делает                                                      |
|--------------|-----------------------------------------------------------------|
| `PROJECTILE` | пули или стрелы (`projectile_shape`): скорость, число, разброс (360 = кольцо) |
| `MELEE`      | `THRUST` — выпад копьём по линии (пробивает); `SWEEP` — замах на 360° вокруг игрока; каждого врага бьёт один раз за удар |
| `ZONE`       | лужа на земле: урон врагам внутри, ускорение игрока внутри      |

Модификаторы снарядов (комбинируются): `pierce` (через скольких врагов проходит,
-1 = бесконечно), `bounces` (рикошеты от стен), `homing_degrees` (самонаведение).
Любой режим может дать игроку временное ускорение (`speed_boost`); ускорения
не складываются, максимум ×1.5 (`Player.MAX_SPEED_MULT`).

### Альт

Альт намного сильнее обычной атаки, но доступен только при полной шкале.
Шкала копится от урона, нанесённого врагам (`EventBus.enemy_damaged`),
сколько нужно — задаётся `WeaponData.alt_damage_needed`. После альта шкала обнуляется.
Это основная ручка баланса: чем больше число, тем реже альт.

### Текущий набор

| Оружие                     | Основной огонь                         | Альт                          |
|----------------------------|----------------------------------------|-------------------------------|
| Святое копьё               | ближний выпад, ускорение ×1.5 на 1 с   | Вихрь Праведника (круг)       |
| Жезл Праведника            | частые слабые самонаводящиеся пули     | Хор Серафимов (кольцо, наведение) |
| Золотой плазменный арбалет | редкое; мощная стрела, пробивает 2     | Плазменный залп (5 стрел)     |
| Посох Горечи               | лужа вокруг игрока, ускоряет внутри    | Жёлчный прилив (большая лужа) |
| Зеркальный раскол          | рикошетящие осколки                    | Каскад отражений (кольцо)     |

### Слоты и подбор

Игрок держит не больше `Player.get_weapon_limit()` единиц оружия (сейчас 2; артефакт Reliquary
повышает). Оружие лежит на `WeaponPedestal` (общая основа с артефактами — `Pedestal`), подбор — касанием (как в Isaac):

- есть свободный слот — оружие занимает его и становится активным, пьедестал пустеет;
- слоты заняты — заменяется оружие в активном слоте, а прежнее остаётся на пьедестале,
  поэтому можно пробовать всё по очереди. Снова сработать пьедестал может, только когда игрок отошёл.

## Враги

`EnemyData` описывает врага целиком; `behavior` выбирает поведение, остальное — числа.

| behavior | что делает | пример |
|----------|------------|--------|
| `RANGED` | держит дистанцию (отступает, если игрок ближе 70%), атакует паттернами из `attacks` (по очереди или случайно, `attack_order`) | Певчий, Слепой Лучник, Херувим-Прялка |
| `CHARGE` | бежит на игрока, контактный урон | Исступлённый, Червеныш |
| `LUNGE` | подходит, замирает с линией-предупреждением, делает рывок, затем стоит уязвимым | Таран |

Любой враг может иметь контактный урон (`contact_damage`) и распадаться при смерти на других
(`split_into` + `split_count`): Выводок → 3 Червеныша. Рывок игрока (i-frames) спасает от контакта и пуль.

Новый враг = новый `.tres` в `data/enemies/`; код трогать не надо, пока хватает этих поведений.

### Паттерны пуль

`BulletPattern` (`data/bullet_pattern.gd`) — вся атака врага как данные; код не нужен.
Новый паттерн = новый `.tres` в `data/patterns/` (номер `p.N` в поле `id`), потом добавить его в `attacks` врага.

- **Прицел (`aim`):** `AT_PLAYER` (в игрока на момент выстрела серии), `TRACK_PLAYER` (каждый выстрел заново), `FIXED` (в фиксированную сторону) + `angle_offset_degrees`.
- **Форма:** `bullets` пуль, `arc_degrees` (360 = кольцо, меньше = веер), `jitter_degrees` (разброс).
- **Серия:** `shots` выстрелов с интервалом `shot_interval`; `rotate_per_shot_degrees` крутит от выстрела к выстрелу (спираль), `rotate_per_use_degrees` — от атаки к атаке.
- **Пуля:** `speed`, `acceleration` (разгон/торможение), `turn_degrees_per_second` (изгиб траектории), `lifetime`, `radius`, `damage`, `color`.
- **Предупреждение:** `windup` секунд — линия (прицельный паттерн) или расширяющееся кольцо (`FIXED`).

`PatternRunner` (`entities/components/pattern_runner.gd`) — компонент, который исполняет паттерн и создаёт `Projectile`;
его используют и враги, и консольная команда `fire`. Боссы позже будут просто цепочкой паттернов.

Паттерны: p.1 Кольцо, p.2 Прицельный веер, p.3 Спираль, p.4 Дробь, p.5 Завихрение, p.6 Нарастающий вал, p.7 Преследование.

## Реестр контента и консоль

**`ContentRegistry`** (автозагрузка) сам находит все `.tres` в `data/weapons`, `data/artifacts`,
`data/enemies`, `data/patterns` и выдаёт их по короткой ссылке: `w.1` — оружие, `a.1` — артефакт, `e.1` — враг, `p.1` — паттерн пуль.
Номер — поле `id` в самом ресурсе, задаётся вручную и **не меняется** (ссылки стабильны).
Работает и имя файла: `w.holy_spear`. Новый `.tres` в папке попадает в реестр без правок кода.
Тестовый этаж собирается из реестра, поэтому комнаты идут в порядке номеров.

**Консоль** (`core/console/`, клавиша `` ` `` / «ё»; игра на паузе, пока она открыта).
`Console` знает только ввод, вывод и реестр команд. Команды — отдельные файлы в `commands/`,
каждый регистрирует себя через `Console.register(ConsoleCommand.create(...))`.
Новая группа команд = новый файл + одна строка в `Console.PROVIDER_PATHS`.

| команда | что делает |
|---------|------------|
| `give` (`g`) `w.N` / `a.N` | выдать оружие (свободный слот или замена активного) или артефакт |
| `drop` `a.N` / `all` | убрать у игрока один экземпляр артефакта или все (проверка стаков и лимитов) |
| `spawn` (`s`) `e.N [кол-во]` | создать врагов в текущей комнате |
| `fire` (`f`) `p.N [here]` | выпустить паттерн пуль из верха комнаты в игрока (`here` — в точку, где стоит игрок) |
| `kill` | убрать всех врагов в комнате |
| `debug` (`d`) `[флаг] [on\|off]` | дебаг-флаги: `infhp`, `infalt`, `infdash`, `onehit` |
| `list` (`l`) `[w\|a\|e\|p]` | номера оружия, артефактов, врагов, паттернов |
| `help` (`h`, `?`) / `clear` | справка / очистка |

Флаги лежат в `DebugState` (автозагрузка); игровой код читает их прямо (`DebugState.infhp`).
Новый флаг = поле + строка в `DebugState.FLAGS`.

Номера сейчас: оружие 1 Святое копьё, 2 Жезл Праведника, 3 Золотой плазменный арбалет,
4 Посох Горечи, 5 Зеркальный раскол · артефакты a.1–a.16 (см. «Артефакты») ·
враги 1 Певчий, 2 Исступлённый, 3 Слепой Лучник, 4 Херувим-Прялка, 5 Таран, 6 Выводок, 7 Червеныш.

## Артефакты

`ArtifactData` — пассивный предмет, только данные (`data/artifacts/*.tres`, номер `a.N` в поле `id`).
Качество `quality` 1–4 как в Isaac: q1–q2 — числа и лёгкие фишки, с q3 — механика без минусов.
`pool` — из какого пула выпадает (сейчас всё «citadel», позже пулы регионов). Хранит:

- `modifiers: Array[StatModifier]` — правки характеристик. Одна правка = стат + `ADD`/`MULT` + значение
  + условие (`ALWAYS`, `HEALTH_HIGH` — здоровье выше 80%, `RECENT_KILL` — 2 с после убийства).
  Статы: макс. здоровье, скорость, урон, скорострельность, скорость пуль, дальность, перезарядка рывка,
  получаемый урон, слоты оружия.
- `perks: Array[Perk]` — механики, которые не сводятся к числам (самонаведение, рикошет, двойной рывок,
  иммунитет к замедлению, Hindsight, осколки, огненный след, Last Rite). Новая механика = новая строка в enum
  `ArtifactData.Perk` + её реализация (искать по имени перка).
- `icon` (64x64) и `body_layer` (слой 32x32 поверх персонажа, порядок — `layer_order`):
  спрайты подставляются в инспекторе, `Player._draw` рисует слои всех взятых артефактов.

**Кто что считает.**
- `PlayerStats` (`entities/player/player_stats.gd`) — единственное место расчёта характеристик:
  `final(stat, база)` = (база + все `ADD`) × все `MULT`; `has_perk(...)`. Остальной код не знает про конкретные артефакты.
  Дробный урон округляется случайно (`roll`): урон 1 с ×1.15 даёт 2 в 15% случаев, поэтому мелкие бонусы не пропадают.
- `Player` применяет статы к движению, стрельбе, получаемому урону, здоровью, лимиту слотов; рывок с `DOUBLE_DASH`;
  пули с `HOMING`/`RICOCHET`/`HINDSIGHT`; `apply_slow()` уважает `SLOW_IMMUNE`.
- `ArtifactEffects` (`entities/player/artifact_effects.gd`) — «живые» эффекты: осколки при убийстве,
  след рывка, волна Last Rite (`Shockwave`).
- Боковая панель HUD получает готовые строки из `PlayerStats.describe()` через `EventBus.stats_changed`.

## Комнаты и этаж

- `RoomData` (`kind`: `HUB`, `WEAPONS`, `ENEMIES`, `ARTIFACTS`) — что в комнате: оружие или артефакты для пьедесталов, либо типы врагов.
- `FloorData` — сетка комнат: клетка `Vector2i` → `RoomData`. Дверь (`Door.Direction`: вверх/вниз/влево/вправо)
  ведёт в соседнюю клетку (вверх = y − 1), если там есть комната; на двери подписано её название.
  Так же будет устроена генерируемая сетка в стиле Isaac.
- `Room` (`rooms/room.gd`) — строит стены, двери и содержимое по `RoomData`, шлёт `door_used`.
  Комната врагов сама возрождает волну после зачистки (для тестов).
- Сцена этажа (`scenes/test_floor.gd`) владеет игроком и HUD, создаёт текущую комнату,
  слушает двери и переключает комнаты. Пули, удары и лужи (группа `transient`) в новую комнату не переходят.
  Комнаты пересобираются при каждом входе, поэтому пьедесталы всегда полные.

### Тестовый этаж 0.0

`TestFloorBuilder` собирает этаж из того, что лежит в `data/` (новый `.tres` подхватывается сам):

```
                [ Враги: тип N ]    ← вверх: по комнате на тип врага (по 2 штуки)
                [ Враги: тип 1 ]
                [     Хаб      ] → [ Артефакты 1 ] → [ Артефакты 2 ] → …   ← вправо: по 5 пьедесталов
                [  Оружие 1    ]    ← вниз: по 5 пьедесталов в комнате
                [  Оружие 2    ]    ← появится, когда оружия станет больше 5
```

Артефакты в комнатах идут по качеству q1–q4, затем по номеру `a.N`. Комнаты пересобираются при входе,
поэтому один артефакт можно брать снова (так проверяются стаки); убрать — `drop`.

Порождённые враги (например Червеныш) в тестовые комнаты не попадают: `in_test_rooms = false`.

## Структура забега (план)

- **Мета-карта = граф регионов.** `RegionData`: тема, пул комнат, пул врагов, босс,
  число этажей, список выходов.
- **`RegionExit`**: целевой регион + условия (босс убит, этажей ≥ N, у игрока есть тег
  снаряжения, выбран маршрут). Недоступные выходы показываются затемнёнными с подсказкой.
- **Этаж:** сетка комнат в стиле Isaac (старт, обычные, сокровищница, магазин, босс).
- **Комната:** враги и паттерны пуль.
- Пост-дивинити: отдельная фаза после победы над Искажённым Божеством.

## Слои стен и пуль

Стены лежат на слоях 1+2. Тела (игрок, враги) сталкиваются со слоем 1.
Пули каждый кадр пускают луч по слою 2 — так работают рикошет и гибель о стену.
Низкие препятствия (пьедесталы, группа `low_obstacle`) пули пропускают.
(Позже: пул пуль и более дешёвая проверка, когда пуль станет много.)

## Дебаг на тестовом этаже

F — заполнить шкалу альта · C — убрать врагов в комнате (следом придёт новая волна).

## Ближайший план

1. Тестовый этаж 0.0 (готово), настройка баланса оружия и врагов по ощущениям.

5. Машина состояний боссов.
